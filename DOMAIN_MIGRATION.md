# Canonical domain migration

Target: https://www.hawksportz.ca. Sandbox only. Dashboard settings have not been verified or changed by this implementation.

1. Record current Production environment settings, Stripe endpoint subscriptions/delivery status, Supabase URL/template/SMTP settings and scheduler target privately. Never copy secrets into notes.
2. Set Supabase Site URL to the target. Add exact redirects https://www.hawksportz.ca/auth/callback and https://www.hawksportz.ca/auth/callback?next=/reset-password. Retain both equivalent localhost:3000 callbacks and temporarily retain existing old-host callbacks. Keep confirmation/recovery templates using {{ .ConfirmationURL }} and verify SMTP separately.
3. Deploy dual-secret webhook support with the current STRIPE_WEBHOOK_SECRET unchanged. Create the new sandbox endpoint https://www.hawksportz.ca/api/stripe/webhook for checkout.session.completed, checkout.session.expired and checkout.session.async_payment_succeeded. Store its secret privately as STRIPE_WEBHOOK_SECRET_NEXT in Vercel Production and redeploy. Old endpoint remains enabled. Primary secret remains required.
4. Set Vercel Production SITE_URL=https://www.hawksportz.ca and redeploy. Keep local SITE_URL unset or http://localhost:3000. Keep sandbox flags and existing keys unchanged. Remote script workers need ORDER_EMAIL_WORKER_URL=https://www.hawksportz.ca; external schedulers must POST directly to /api/internal/order-emails with existing bearer authentication. Redirects are refused by the script.
5. Test canonical sandbox purchase, webhook settlement, refresh and same-browser receipt. Fresh private session and unrelated account must get 404. Test wrong/missing Origins, resume/cancel, expiration/release, duplicate events, late expiration and email deduplication. Verify signup/confirmation, login/logout, recovery/reset, expired/replayed links and account orders using a controlled mailbox in the initiating browser. Check actual Stripe and Resend delivery status.
6. Resolve outstanding old sessions and failed deliveries before disabling the old webhook. Promote the new secret to STRIPE_WEBHOOK_SECRET and remove STRIPE_WEBHOOK_SECRET_NEXT in the same configuration update, then redeploy and verify again. Do not blanket-redirect the old host while old guest receipts or callbacks still need it.

Cookies, carts, IndexedDB designs and resume pointers do not transfer across origins. Sign in again on www; use existing design export/import where needed. Old Stripe sessions retain their return URLs. Preserve old-host receipt access in the original browser. Do not add URL-only receipt authorization or transfer raw cookie secrets.

No DNS, SQL, inventory-policy, Supabase API URL, image-host, sender-address or Server Action allowedOrigins changes are required. Preserve OVH email records. Roll back application origin configuration only with coordinated auth and scheduler settings; keep working webhook verification active and reconcile payments before retries. Do not release uncertain reservations manually.
